# Contributing to ShareShield

This is a **private, two-developer project** while repository ownership and IP terms are being resolved. Only approved collaborators should contribute.

## Collaboration workflow
1. Discuss the task and agree on its requirements.
2. Work on a topic branch such as `docs/readme`, `frontend/upload-ui`, or `backend/pdf-redaction`.
3. Keep changes focused and use meaningful commit messages.
4. Open a pull request into `main` with a summary and any relevant tests.
5. Have the other active developer review before merging when practical.
6. Never commit real personal data, confidential documents, credentials, or copied code without compatible rights.

## Responsibility split
- **Backend/PDF & verification:** 2017 Mac developer.
- **Frontend & integration:** 2019 Mac developer.
- **Both:** requirements, reviews, security tests, documentation and demo rehearsal.

## Before submitting changes
- Verify no secrets or private documents are present.
- Check that new dependencies have compatible licensing terms.
- Note unsupported file types or failed verification checks.
- Ensure documentation reflects **implemented** behavior rather than planned features.
- Disclose third-party code or content sources and copyright notices when required.

## Intellectual property
Contributions may affect copyright and patent inventorship. Repository access or a GitHub commit does not itself resolve ownership or create an assignment. The active developers, other listed project participants, and applicable college policies should be reviewed before commercial licensing or public release. See [IP and licensing](docs/IP_AND_LICENSING.md).
