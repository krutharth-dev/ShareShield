# Smart Redaction Preferences — Demo workflow

This is a **local prototype** feature. The app does not run silently over your
WhatsApp, Gmail or other applications. A person must explicitly upload a file.

## How to use it

1. Choose an image or PDF (or DOCX/PPTX/XLSX/CSV/TXT for text patterns).
2. Under **What would you like to protect?**, select the desired categories.
3. Keep **Protect every recognized occurrence** selected to redact recognized
   repetitions of the same identifier on other pages and elsewhere in the file.
4. Scan and review all candidate detections individually.
5. Use the PDF/image preview to draw manual boxes around missed IDs, photos,
   signatures, names, addresses, handwritten fields, QR-like codes and barcodes.
6. Choose a mask appearance. **Blackout is safest and recommended for personal
   identification.** Blur/pixelate is only for face candidates and manual areas;
   detected text/QR always gets permanent black-box removal.
7. Export and inspect every page of the result. Check the verification report;
   an `UNVERIFIED` result requires manual inspection.

## Implemented categories

- **Aadhaar:** checksum-validated Aadhaar numbers, reviewable 12-digit ID
  candidates (including checksum-invalid OCR readings), and labeled VID.
- **Name and address:** conservatively recognized English text immediately
  following a `Name:` or `Address:` label; multilines, handwriting,
  Kannada and unlabeled address blocks may be missed.
- **DOB:** English-labeled DOB/date-of-birth entries in numeric format.
- **Face/photo:** local Haar frontal-face detector proposes bounding rectangles.
  Photos with profiles, tiny faces or difficult lighting can be missed; use
  manual boxes instead.
- **QR codes:** local QR detection proposes boxes. PDF417/Aztec/1-D barcodes,
  dense/unusual QR-like symbols or damaged codes require manual boxes.
- **Phone/email, PAN, UPI, payment cards, IFSC:** pattern-based candidates.
- **Other areas:** draw a manual mask on a PDF/image (no generic AI detector).

All recognition is **best effort**. Selected preferences control which detected
candidates are initially checked; the scan is not a machine-learning guarantee.
The user can select, deselect or manually draw additional regions.

## Why a repeated Aadhaar number might survive

OCR may miss a glyph, separate a number into lines or incorrectly transcribe a
digit. A checksum-validated match can fail even when a number is visible. The
12-digit candidate rule improves coverage but may flag unrelated numbers. The
repeated-identifier option covers **recognized equal values**, not invisible or
incorrectly recognized duplicates. Zoom through the entire original and output;
always manually mask any missed instance. The **PASS_SCOPED** verification
only checks selected *recognized* information, not all private content.

## Redaction/export safety

- Blackout on PDFs uses native PyMuPDF redaction annotations and garbage-cleaned
  output. The exported file is not a full metadata/annotation/attachment sanitizer.
- Blur/pixelate on PDFs rebuilds each page as a flat raster image. The original
  searchable text layer is absent, but blur and pixelation can still reveal or
  allow inference of sensitive information.
- Every exported image is a newly rendered PNG. Original EXIF metadata is not
  carried over. Manual masks are user-selected and not proven exhaustive.
- Text identifiers and QR regions are **always blacked out**, even when the
  global visual option is blur or pixelate.
- Automatically detected face/QR regions and all blurred/pixelated or manually
  selected masks result in **UNVERIFIED**; the user must review every export.
- The frontend deliberately blocks a flagged selected-value match.
- No network-based facial recognition, identification, storage account or
  automatic continuous scanning is part of this mini-project build.

## Setup on the 2017 Intel Mac running macOS Ventura 13

The visual detector uses OpenCV 4.10.0.84, with a prebuilt Ventura-compatible
Intel wheel. Tesseract OCR was installed separately using MacPorts.

~~~bash
cd ~/Desktop/ShareShield
git switch integration/deployable-web-app
git pull --ff-only origin integration/deployable-web-app
bash scripts/setup-macos.sh
bash scripts/check-ready.sh
.venv/bin/python -m pytest backend/tests -v
bash scripts/start-demo.sh
~~~

You should see the local backend connection. Visit
http://127.0.0.1:8000/health and check `ocr_available` and
`vision_available`. Use fictional test fixtures generated by:

~~~bash
.venv/bin/python scripts/generate-demo-files.py
~~~

Do not use real identity documents as test fixtures or commit them to GitHub.
Even a redacted sample screenshot may contain an unredacted VID, QR-like code,
DOB, photo, name or address. Test with synthetic information first.

## Final demonstration review controls

- **Whole-export rescanning:** the exported file is reopened and scanned for
  *all* recognized patterns, even categories the reviewer did not select.
  Previously selected values or any remaining high-priority identifiers result
  in a `FLAG` and the website withholds the export. Medium/low-priority
  candidates remaining cause an `UNVERIFIED` result and must be inspected.
- **Safer audit JSON:** the downloadable report includes counts, categories,
  pages, selected count, output SHA-256, categories requested, warnings and
  manual-review progress, but intentionally omits the original values of
  detected identifiers.
- **Editable manual masks:** after drawing a rectangle, choose its box number
  to nudge it in four directions, enlarge/shrink it or delete it. Undo/redo
  affects drawing and editing. Zoom up to 300% for small print.
- **Before/after comparison:** adjust the reveal slider on each output page.
  Check every page of the exported file and mark its review checkbox.
- **Acknowledgement before download:** the browser disables export until each
  image/PDF page is marked reviewed and the user acknowledges that automated
  detection is incomplete. This is a front-end safeguard, not access control.
- **PDF cleanup:** after native black-box redactions, the export attempts to
  remove standard metadata, attached files, page annotations and links. PDF
  scripts, form data, hidden content and accessibility text still need
  specialist inspection. Blur/pixelate exports remain rasterized.

## Important limits

More OCR attempts and better candidate rules help, but **cannot guarantee
that small, repeated, multilingual, handwritten or poorly scanned Aadhaar/VID
content is detected**. Manual review and correction remain essential. Never
treat `PASS_SCOPED` as certification that a real identity document is safe.
