## Security, accuracy and remaining limitations

- Public synthetic-only policy unchanged. No user authentication, tenant accounts,
  per-user rate limits, malware sandbox or independent penetration test. Upload
  admission is per process; a distributed attacker can still deny service.
- Standard document parsers still run in the main process's worker thread.
  Cancellation preserves its CPU slot but does not hard-kill arbitrary native
  parsing. Large legal inputs/complex PDFs or workbooks can still exhaust RAM.
  Full request CPU/RSS isolation is a release blocker for real private documents.
- Temporary multipart spooling remains possible and bounded per admitted request.
  No document logging/storage added. Review findings remain in process memory
  for their expiry window. Platform retention is not independently audited.
- Office/XLSX formulas, caches, comments, revision history, embedded objects and
  other hidden content are not comprehensively sanitized. Existing conservative
  UNVERIFIED semantics remain. Blackout removes selected native PDF text, but
  that does not certify all PDF hidden content. Blur/pixelation are not guaranteed
  irreversible. SHA-256 binds the report to output bytes, not anonymity.
- Handwriting is pretrained PP-OCRv5/RapidOCR, never custom-trained here. The
  font sample is not genuine pen handwriting. Real-writer sensitive-field recall
  and complete mask coverage are **not measured**: no labeled consent-safe
  real-writing benchmark was supplied. Manual visual review remains essential.
- Model hashes are checked at build time. Worker network monkeypatching prevents
  the supported Python download path but is not OS-enforced network isolation.
  Font/license URLs and most Python version ranges are not a fully locked,
  hermetic supply chain. Vulnerability scans are time-bound, not proof of safety.
- Physical iPhone Safari, Android Chrome, Windows and responsive viewport matrix
  are not verified in this audit. Cloud browser exposed no viewport controls.
  Candidate UI is unchanged except the development proxy. No compatibility claim
  is inferred from successful desktop Chromium or a CSS review.
- Public API schema/docs remain intentionally reachable; there is no debug mode
  or secret in those schemas. Access control must be reviewed before sensitive use.
- PR #3 is still a draft from integration to main and contains obsolete Cloudflare
  claims. This candidate uses a separate PR into integration; do not merge #3 as
  evidence of current deployment safety.
